# เชื่อม COM LAB RESCUE กับ Google Sheets

เอกสารนี้เป็น handoff สำหรับเปิดใช้การบันทึกออนไลน์จริง โค้ด Apps Script และโครงข้อมูลเตรียมครบแล้ว สิ่งที่ต้องทำในบัญชีของผู้สอนคือสร้างชีต รัน setup อนุญาตสิทธิ์ และ deploy Web app จากนั้นนำ URL มาใส่ในเกม

สถานะการตรวจ: ทดสอบตรรกะด้วย Google services จำลองในเครื่องแล้ว ยังไม่ได้ deploy หรือทดสอบการเขียนลงบัญชี Google จริงของผู้ใช้

## สิ่งที่ต้องมี

- บัญชี Google ที่ได้รับอนุญาตให้สร้าง Google Sheets และ deploy Apps Script Web app
- ไฟล์ apps-script/Code.gs
- ไฟล์ apps-script/Questions.gs
- ไฟล์ apps-script/appsscript.json
- ตัวเกม COM-LAB-RESCUE.html หรือเว็บเกมที่เสิร์ฟจาก dist/

ระบบนี้ไม่ใช้ API key, service-account key หรือรหัสผ่านฐานข้อมูล ตัวเกมต้องทราบเพียง URL Web app ของ Apps Script ส่วน Google Sheet เก็บไว้ส่วนตัวได้

## 1. สร้าง Google Sheet

1. ลงชื่อเข้าใช้บัญชีที่ผู้สอนจะใช้เป็นเจ้าของข้อมูล
2. สร้าง Google Sheet ใหม่ ตั้งชื่อเช่น COM LAB RESCUE ผลการเล่น
3. คงการแชร์เป็น Restricted/จำกัด ให้เฉพาะผู้สอนหรือผู้ดูแลที่ต้องดูข้อมูลเข้าถึงได้
4. ในชีต เลือก Extensions → Apps Script หรือ ส่วนขยาย → Apps Script

การเปิด Web app ให้ผู้เล่นเรียก API ไม่ได้หมายความว่าต้องเปิดตัวชีตเป็นสาธารณะ API จะทำงานภายใต้สิทธิ์ของเจ้าของตามการตั้งค่า deployment [อ้างอิง Google](https://developers.google.com/apps-script/guides/web)

## 2. ใส่โค้ดให้ครบ

1. ใน Apps Script editor เปิด Code.gs แล้วแทนเนื้อหาด้วยไฟล์ apps-script/Code.gs ที่ให้มา
2. กดเครื่องหมาย + ข้าง Files → Script ตั้งชื่อ Questions แล้ววางเนื้อหาจาก Questions.gs ให้ครบ
3. ไป Project Settings → เปิด Show "appsscript.json" manifest file in editor
4. กลับ Editor เปิด appsscript.json แล้วใช้เนื้อหาจากไฟล์ที่ให้มา
5. บันทึกทุกไฟล์

Manifest ใช้ V8 และเขตเวลา Asia/Bangkok พร้อมขอสิทธิ์ Google Sheets สำหรับอ่าน/เขียนชีตที่สคริปต์ใช้ ไม่มีการขอสิทธิ์ Gmail หรือการส่งข้อความ

ห้ามใส่เฉพาะ Code.gs โดยไม่มี Questions.gs เพราะเซิร์ฟเวอร์ต้องใช้เฉลยชุดเดียวกับเกมเพื่อตรวจคะแนน

## 3. รัน setup และอนุญาตสิทธิ์

1. เลือกฟังก์ชัน setup จากรายการด้านบน
2. กด Run/เรียกใช้
3. เลือกบัญชีเจ้าของชีตและตรวจคำขอสิทธิ์ Google Sheets จากโปรเจกต์ที่เพิ่งสร้าง
4. อนุญาตตามนโยบายบัญชีที่ใช้ หากองค์กรบล็อกการใช้งานต้องให้ผู้ดูแลอนุญาตก่อน
5. กลับ Google Sheet ตรวจว่ามีแท็บใหม่ครบ:

| แท็บ | สิ่งที่ใช้เก็บ |
| --- | --- |
| players | ชื่อ รหัสผู้เรียน กลุ่ม ชื่อเล่น และ hash สำหรับสิทธิ์ของผู้เล่น |
| sessions | รอบการเล่น เวลา คะแนน ความก้าวหน้า เหรียญ และสถานะ |
| answers | คำตอบแรกของแต่ละข้อและเวลารับทราบคำอธิบาย |
| events | รหัสการกระทำสำหรับส่งซ้ำโดยไม่เพิ่มคะแนน |

setup ใช้ชีตที่เปิดอยู่เป็นเป้าหมายและบันทึก SPREADSHEET_ID ใน Script Properties ให้โดยอัตโนมัติ เพื่อให้ Web app เปิดชีตถูกไฟล์แม้ไม่มีบริบทหน้าชีตขณะทำงาน

รัน setup ซ้ำได้โดยไม่ล้างข้อมูล หากหัวตารางเดิมไม่ตรงจะหยุดพร้อม schema_mismatch เพื่อให้ตรวจสอบก่อน ไม่แก้ข้อมูลผู้เรียนทิ้งเอง

### ถ้าใช้ Apps Script แบบ standalone

ใน Project Settings → Script Properties เพิ่ม:

| Property | Value |
| --- | --- |
| SPREADSHEET_ID | ID ของ Google Sheet ที่ต้องการ |

ID คือส่วนที่อยู่หลัง /d/ และก่อน /edit ใน URL ของ Google Sheet จากนั้นรัน setup ด้วยบัญชีที่มีสิทธิ์แก้ชีตนั้น ส่วนนี้ไม่จำเป็นถ้าสร้างสคริปต์จาก Extensions ของชีตตามขั้นตอนปกติ

## 4. Deploy เป็น Web app

1. มุมขวาบนกด Deploy → New deployment
2. เลือกประเภท Web app
3. ใส่คำอธิบาย เช่น COM LAB RESCUE v1
4. Execute as เลือก Me/ฉัน ซึ่งเป็นเจ้าของชีต
5. Who has access เลือก Anyone/ทุกคน หากบัญชีและนโยบายสถาบันอนุญาต
6. กด Deploy แล้วดำเนินการอนุญาตสิทธิ์ที่จำเป็น
7. คัดลอก Web app URL ที่ลงท้าย /exec

รูปแบบ:

~~~text
https://script.google.com/macros/s/DEPLOYMENT_ID/exec
~~~

ใช้ /exec สำหรับผู้เรียน ลิงก์ /dev ใช้ทดสอบโดยผู้ที่มีสิทธิ์แก้สคริปต์ จึงไม่ใช่ลิงก์ใช้งานทั่วไป [อ้างอิง Google](https://developers.google.com/apps-script/guides/web)

หากบัญชีองค์กรไม่มีตัวเลือก Anyone ให้ผู้ดูแลตรวจนโยบาย Web app ขององค์กรก่อน การเลือกเฉพาะผู้ลงชื่อเข้าใช้ Google อาจทำให้ fetch ของเกมได้รับหน้าเข้าสู่ระบบแทน JSON โค้ดนี้ไม่ได้มี flow Google OAuth สำหรับผู้เรียนและไม่ได้ใช้วิธีหลบข้อจำกัดบัญชี

## 5. ตรวจ Web app ก่อนใส่ในเกม

เปิด /exec URL ในหน้าต่างส่วนตัวหรือเบราว์เซอร์ที่ไม่ได้ลงชื่อเข้าใช้บัญชีเจ้าของ ควรได้ JSON ลักษณะนี้:

~~~json
{
  "ok": true,
  "data": {
    "ok": true,
    "storage": "google-sheets",
    "version": "1.0.0"
  }
}
~~~

ถ้าต้องลงชื่อเข้าใช้หรือเห็นหน้า HTML แทน JSON ให้แก้สิทธิ์ deployment ก่อน หากได้ setup_required ให้รัน setup ถ้าได้ question_bank_missing ให้ตรวจ Questions.gs

Health check ยืนยันว่า URL เรียกใช้สคริปต์และอ่านโครงชีตได้ แต่ยังต้องทดสอบการลงทะเบียนและเขียนข้อมูลจริงในขั้นที่ 7

## 6. ใส่ URL ในเกม

### ตั้งค่าจากตัวเกม

1. เปิดเกม
2. กดปุ่มการตั้งค่า
3. เลือก เชื่อม Google Sheets ของผู้สอน
4. วาง URL /exec
5. กด ตรวจสอบและบันทึก
6. หลังเชื่อมสำเร็จ ลงทะเบียนผู้เล่นเพื่อเริ่มรอบออนไลน์

ถ้าเคยเริ่มเล่นในโหมดฝึกในเครื่องก่อนแล้ว ให้เก็บผลเดิมและใช้ เปลี่ยนผู้เล่น เพื่อเริ่มรอบที่ผูกกับ Google Sheets ผลฝึกเก่าไม่ถูกนำไปสวมเป็นผลออนไลน์

URL ที่กรอกในหน้าตั้งค่าจำเฉพาะ browser นั้น เหมาะสำหรับการทดสอบครั้งแรก

### ใส่ URL ในไฟล์เกมสำหรับแจกผู้เรียน

แก้เฉพาะ googleScriptUrl ใน config.json:

~~~json
{
  "googleScriptUrl": "https://script.google.com/macros/s/DEPLOYMENT_ID/exec"
}
~~~

ถ้า config.json มีค่าอื่นอยู่ ให้คงค่าเหล่านั้นไว้ จากนั้นรัน:

~~~bash
npm run build
~~~

แจก COM-LAB-RESCUE.html ที่สร้างใหม่ หรืออัปโหลดไฟล์ใน dist/ ไปยัง static host ที่ใช้ ผู้เรียนที่เปิดครั้งแรกจะใช้ URL ที่ฝังในไฟล์ได้โดยไม่ต้องกรอกเอง ถ้า browser เคยบันทึก URL เก่าไว้ ให้เปลี่ยนในหน้าตั้งค่าของ browser นั้นด้วย

Google Web app เป็น API สำหรับเก็บข้อมูล ตัวเกมต้องมีไฟล์ HTML หรือเว็บโฮสต์แยกตามที่แจก ไม่ต้องเปิด Spreadsheet ให้ผู้เรียนแก้ไข

## 7. ทดสอบการเขียนจริงก่อนใช้งานส่งงาน

ทำหนึ่งรอบด้วยข้อมูลทดสอบที่แยกจากนักเรียนจริง:

1. เชื่อม URL แล้วลงทะเบียนรหัสทดสอบใหม่ เช่น TEST-001
2. ตรวจแท็บ players ว่ามีหนึ่งแถว ชื่อ รหัสและกลุ่มตรงกับที่กรอก คอลัมน์ token_hash เป็น hash ไม่ใช่ token ดิบ
3. เริ่มเกม ตรวจ sessions ว่ามีรอบใหม่ คะแนนเริ่ม 0 เต็ม 120 และสถานะ in_progress
4. ตอบหนึ่งข้อแล้วรับทราบคำอธิบาย ตรวจ answers ว่ามีหนึ่งแถว และ acknowledged_at ถูกบันทึกหลังรับทราบ
5. โหลดหน้าเกมใหม่ใน browser เดิม ต้องกลับมาเล่นชุดคำถามเดิมต่อได้ คะแนนไม่เพิ่มเพราะโหลดซ้ำ
6. เล่นจบทั้งสามด่าน ตรวจ sessions: status เป็น completed, มี ended_at และ correct_count + wrong_count = 12
7. ตรวจ score = correct_count × 10 และเหรียญตรงเกณฑ์
8. เปิดสถิติผู้เล่น ตรวจว่าชื่อเล่นและคะแนนตรงกับชีต
9. ใช้อีก browser ลงทะเบียนอีกคนในกลุ่มเดียวกัน แล้วตรวจว่า Dashboard นับสองคน ข้อมูลของอีกกลุ่มไม่ปะปน
10. ระหว่างรอบออนไลน์ทดลองตัดเน็ตสั้น ๆ แล้วกลับมาออนไลน์ รอให้แถบบันทึกยืนยันสำเร็จและตรวจว่าไม่มีคะแนนบวกซ้ำ

หลักฐานที่ควรเก็บสำหรับส่งงาน: ลิงก์เกมที่เปิดได้จริง ภาพหน้าสรุปผล และภาพแถวข้อมูลทดสอบที่ตรงกัน โดยเลือกภาพที่ไม่เผย token หรือข้อมูลนักเรียนจริงที่ไม่เกี่ยวข้อง

## 8. เมื่อแก้โค้ดหรือเพิ่มคำถาม

1. แก้ source ของเกมและ data/question-bank.json
2. อัปเดต Questions.gs ให้ตรงกับชุดใหม่ และเพิ่ม bank_version ให้ตรงกันทั้งสองไฟล์ทุกครั้งที่แก้คำถาม ตัวเลือก เฉลย คำอธิบาย ประเภท ระดับความยาก หรือคะแนน
3. แก้โค้ดใน Apps Script แล้วบันทึก
4. Deploy → Manage deployments → เลือก deployment เดิม → Edit
5. เลือก Version ใหม่ แล้ว Deploy เพื่อให้ /exec ใช้โค้ดใหม่ โดยเก็บ URL เดิมถ้าเป็นการอัปเดต deployment เดิม
6. build ตัวเกมใหม่และทดสอบหนึ่งรอบอีกครั้ง

การกด Save ใน editor อย่างเดียวไม่เปลี่ยนโค้ดของ deployment /exec ที่ผูกกับเวอร์ชันเก่า รัน setup ซ้ำเฉพาะเมื่อเตรียมชีตใหม่หรือต้องตรวจโครง ไม่ต้องรันทุกครั้งที่นักเรียนเล่น

ก่อนเปลี่ยนชุดคำถาม ให้ผู้เรียนจบรอบและรอส่งข้อมูลครบก่อน พร้อมเก็บไฟล์ HTML รุ่นเดิมไว้สำหรับรอบที่ยังไม่จบหรือมีข้อมูลรอส่ง แม้ Apps Script จะเก็บ snapshot คำถามของรอบเดิมไว้ แต่การเล่นต่อออฟไลน์ต้องใช้ HTML ที่มีคลังคำถามตรงกับรอบนั้น

HTML รุ่นใหม่จะปฏิเสธรอบที่ bank_version หรือเนื้อหาคำถามที่เปิดเผยไม่ตรงกัน เพื่อไม่ตรวจคำตอบด้วยเฉลยคนละชุด ข้อมูลค้างเดิมจะถูกเก็บไว้โดยไม่เขียนทับและยังส่งออกได้ ให้เปิด HTML รุ่นเดิมใน browser เดิมเพื่อเล่นต่อหรือส่งข้อมูลให้ครบ อย่าล้างข้อมูล browser เพื่อแก้ปัญหานี้ เมื่อรอบรุ่นเก่าจบหรือยุติและส่งข้อมูลครบแล้ว รุ่นใหม่จะเก็บผลนั้นเป็นประวัติและคงโปรไฟล์ไว้สำหรับเริ่มรอบใหม่ ส่วน Dashboard แยกสถิติตาม bank_version

API ไม่ส่งเฉลยทั้งหมดมากับคำถาม จึงตรวจจับการเปลี่ยนเฉพาะเฉลยหรือคำอธิบายล่วงหน้าจาก snapshot สาธารณะไม่ได้ การเพิ่ม bank_version ทุกครั้งที่แก้ส่วนนี้และแจก HTML ที่ build ตรงกับ Questions.gs เป็นเงื่อนไขที่ต้องรักษา

## ปัญหาที่พบบ่อย

| อาการ | ตรวจหรือแก้อย่างไร |
| --- | --- |
| URL ไม่ผ่านการตรวจในเกม | ใช้ URL รูปแบบ script.google.com/macros/s/.../exec ไม่ใช่ลิงก์แก้โค้ด, ลิงก์ชีต หรือ /dev |
| ต้องล็อกอิน Google / ได้ HTML แทน JSON | ตรวจ Who has access และนโยบายองค์กร ต้องใช้ deployment ที่ผู้เรียนเรียกได้ตาม flow นี้ |
| setup_required | รัน setup ด้วยบัญชีเจ้าของและอนุญาตสิทธิ์ครบ |
| configuration_required | เปิดจาก Extensions ของชีต หรือกำหนด SPREADSHEET_ID ใน Script Properties |
| question_bank_missing / question_bank_invalid | ตรวจว่า Questions.gs ครบและมี bank version กับคำถามครบกลุ่ม |
| bank_version_mismatch / bank_snapshot_mismatch | HTML กับคลังคำถามของรอบไม่ตรงกัน เก็บข้อมูลค้างไว้และเปิด HTML รุ่นที่ตรงกันใน browser เดิม; รอบใหม่ต้องใช้ HTML กับ Questions.gs รุ่นเดียวกัน |
| schema_mismatch | มีแท็บชื่อเดียวกันแต่หัวตารางไม่ตรง อย่าล้างข้อมูลเดิม ให้ตรวจเทียบ schema หรือใช้ชีตใหม่ |
| recovery_required | รหัสผู้เรียนและกลุ่มนี้ลงทะเบียนแล้ว ใช้ browser เดิมหรือติดต่อผู้สอน ไม่มีการคืน token ให้เพียงเพราะรู้รหัสนักเรียน |
| busy / service_unavailable | รอสักครู่แล้วให้คิวส่งซ้ำ ตรวจหน้า Executions และโควตา ถ้าเกิดซ้ำให้ลดการเรียก/แบ่งรอบเข้าเล่น |
| ข้อมูลค้างรอซิงก์ | คงหน้าเกมไว้จนเน็ตกลับ ห้ามล้างข้อมูลเว็บไซต์ก่อนส่งสำเร็จ ตรวจ URL และ deployment ถ้าไม่หาย |
| คะแนนบนชีตไม่เปลี่ยนหลังแก้ค่าด้วยมือ | record_json และ answers เป็นข้อมูลหลัก ไม่ควรแก้คอลัมน์แสดงรายงานเพื่อเปลี่ยนผลเกม |
| CORS / Failed to fetch | ตรวจ /exec, deployment anonymous access ตามที่อนุญาต, redirect, เครือข่าย และ response ว่าเป็น JSON ใช้ text/plain กับ envelope ที่มีให้ |

ห้ามแก้ CORS ด้วย mode: no-cors เพราะ browser จะคืน opaque response ที่อ่านผลบันทึกไม่ได้ และห้ามใช้การเปิดชีตสาธารณะเป็นทางแก้สิทธิ์ API

โค้ดใช้ fetch ที่ติดตาม redirect ตามปกติ เพราะ ContentService ส่งผลผ่าน URL ชั่วคราวใน script.googleusercontent.com [อ้างอิง Google](https://developers.google.com/apps-script/guides/content)

## ดูแลข้อมูลและขอบเขตการใช้งาน

- คงชีตเป็นส่วนตัวและให้สิทธิ์เฉพาะผู้ที่ต้องจัดการข้อมูลจริง
- คอลัมน์ record_json เก็บข้อมูลต้นฉบับ อย่าลบหรือแก้บางส่วนด้วยมือ หากต้องวิเคราะห์ให้ทำชีตสำเนาหรือแท็บรายงานแยก
- สำรองไฟล์ด้วยการทำสำเนา Google Sheet ตามรอบที่ผู้สอนกำหนด หากย้ายไปใช้ชีตสำเนา ให้เปิด Apps Script ของชีตใหม่นั้น รัน setup และ deploy/ทดสอบให้ชี้เป้าหมายใหม่
- การล้างข้อมูล browser อาจทำ token และคิวที่ยังไม่ซิงก์หาย ระบบนี้ไม่มีหน้า recovery ข้ามเครื่องหรือระบบบัญชีสถาบัน
- สำหรับคะแนนทางการ ให้ผู้สอนกำหนดวิธีตรวจตัวผู้เรียนและการกู้บัญชีเพิ่มเติมตามระบบที่ใช้อยู่

Apps Script และ Sheets มีโควตาและข้อจำกัดการทำงานพร้อมกัน ระบบนี้ใช้ ScriptLock เพื่อรักษาความถูกต้อง และอ่าน/เขียนเป็นช่วง จึงเหมาะเริ่มใช้งานระดับกลุ่มเรียนและทดสอบกับจำนวนคนจริงก่อนเพิ่มขนาด ไม่ได้ยืนยันว่ารองรับผู้เล่นพร้อมกันหลักพัน [โควตาปัจจุบันของ Google](https://developers.google.com/apps-script/guides/services/quotas)
