# ผลตรวจ COM LAB RESCUE

ตรวจเมื่อ 8 พฤศจิกายน 2026 โค้ดสำหรับบันทึกออนไลน์ใช้ Google Apps Script + Google Sheets เท่านั้น

## ตรรกะเกมและการบันทึก

รัน `npm test` สำหรับ store, Apps Script และการเชื่อมต่อระหว่างสองส่วน โดยใช้โค้ดจริงของทั้ง frontend และ backend จำลองเฉพาะบริการของ Google และขอบเขต network ผลสุดท้ายผ่าน 41/41 tests (store 18, backend 16, integration 7) ไม่มี fail หรือ skip และบันทึกไว้ในตาราง release ของ HANDOFF.md

ครอบคลุมการสุ่ม 12 ข้อจากคลัง 18 ข้อ ความยาก/รูปแบบครบทุกด่าน การบังคับคำตอบแรก ด่านที่ยังล็อก เหรียญและเกณฑ์ผ่าน การเก็บลำดับเดิมเมื่อกลับมาเล่นต่อ การตรวจสิทธิ์ token การเก็บข้อมูลข้อความลง Sheets โดยไม่กลายเป็นสูตร และ Dashboard แยกกลุ่มเรียน

ทดสอบกรณีคำตอบกลับจาก Google หายหลังบันทึกสำเร็จ การเล่นต่อออฟไลน์จนจบรอบแล้วส่งคิว 24 รายการ การเขียนชีตขาดช่วงแล้วกู้ยอดรวมจากคำตอบเดิม และการไม่สร้างผู้เล่นโหมดฝึกโดยเงียบ ๆ เมื่อเชื่อม Google ไม่สำเร็จ

## การเล่นผ่านเบราว์เซอร์

| ขั้นตอน | ผลที่สังเกตจริง |
| --- | --- |
| ส่งแบบฟอร์มลงทะเบียนว่าง | แจ้งข้อผิดพลาดครบ 4 ช่องและนำ focus ไปช่องแรก |
| ลงทะเบียนข้อมูลจำลองและเริ่ม | เปิดสถานี 1 ได้ สถานี 2–3 ยังล็อก |
| ตอบผิด 1 ข้อ | ไม่เพิ่มคะแนน แสดงคำตอบที่ถูกและคำอธิบาย |
| โหลดหน้าใหม่หลังตอบแต่ยังไม่กดซ่อม | กลับมาเจอข้อเดิม คำตอบเดิมถูกล็อก คะแนนไม่เพิ่มซ้ำ |
| เล่นครบสามสถานี | ได้ 110/120, ถูก 11 ผิด 1, 91.7%, เหรียญทอง และคำแนะนำด่านที่ตอบผิด |
| ทบทวนคำตอบ | แสดงครบทั้ง 12 ข้อพร้อมเฉลยและคำอธิบาย |
| Dashboard ในเครื่อง | จำนวนผู้เล่น คะแนนเฉลี่ย/สูง/ต่ำ อันดับ เวลา และเหรียญตรงกับรอบที่จบ |
| พักเกม / กลับหน้าหลัก / เปลี่ยนผู้เล่น | ปุ่มทำงาน มีข้อความอธิบายก่อนออกจากตัวตนปัจจุบัน |
| Google URL ไม่ถูกต้อง | แจ้งรูปแบบ /exec, ตั้ง aria-invalid และนำ focus กลับช่อง URL |
| Dialog และคีย์บอร์ด | เปิด/ปิดได้ด้วยปุ่มและ Escape; native dialog เก็บ focus ภายใน |
| หน้าจอแคบ | ตรวจที่ความกว้าง CSS 454 px ผ่าน browser zoom 300%; หน้าเริ่ม ลงทะเบียน Dashboard และคำถามไม่มี horizontal overflow |

การตรวจจอแคบเป็น browser viewport บน desktop ไม่ใช่การทดสอบอุปกรณ์มือถือจริง ทุกไฟล์ที่แจกไม่มีข้อมูลผู้เล่นจำลองจาก browser test ฝังไว้

## ภาพและสภาพแวดล้อม

ตรวจภาพ SVG สำรองรุ่นสุดท้ายใน browser แล้ว มีห้องคอม 3 สถานี หุ่นยนต์ และไฟความคืบหน้า พร้อมปุ่มสถานีที่กดได้เมื่อปลดล็อก

เครื่องทดสอบปิด WebGL โดยรายงาน GL_VENDOR/GL_RENDERER เป็น Disabled จึงตรวจการเล่นผ่านฉากแบบเบา ฉาก Three.js จริงอยู่ใน src/scene.js และ bundle แต่ยังไม่ได้ยืนยันภาพเคลื่อนไหวหรือประสิทธิภาพบน GPU จริง ควรเปิดไฟล์บน browser ที่รองรับ WebGL2 เพื่อดูฉากสามมิติก่อนเผยแพร่ใช้งาน

## Static checks

- Build เป็น HTML เดี่ยวสำเร็จ พร้อม Three.js และฟอนต์ในไฟล์ ไม่ต้องเรียก CDN ตอนเล่น
- DESIGN.md ผ่าน designmd lint: 0 errors, 0 warnings และตรวจ token ตรง CSS
- Static server ผ่าน 9 HTTP scenarios รวม GET/HEAD, traversal, symlink escape และไม่เปิด source/API
- ตรวจ source ไม่เหลือ backend หรือคำสั่งของ SQLite
- ผล audit จาก frontend-design-premium เก็บไว้ใน audit-static.json เครื่องมือแจ้งปุ่ม 5 ปุ่มใน template ว่าไม่พบ action เนื่องจากตรวจเฉพาะ inline onclick แต่โปรเจกต์ใช้ document click delegation ผ่าน data-action ใน app.js ได้ตรวจจริงครบทั้งกลับหน้าหลัก วิธีเล่น สถิติ การตั้งค่า และสถานะบันทึกแล้ว จึงเป็นข้อจำกัดของ static detector ไม่ใช่ปุ่มที่ไม่มีการทำงาน

## สิ่งที่ต้องตรวจหลังตั้งค่าบัญชี Google

ยังไม่ได้สร้างหรือ Deploy Web app ในบัญชีของผู้ใช้ และยังไม่ได้เขียน Google Sheet จริง ต้องทำตาม GOOGLE-SHEETS-SETUP.md แล้วตรวจสิทธิ์, /exec URL, ContentService redirect/CORS, แถวข้อมูลจริง และจำนวนผู้เล่นพร้อมกันก่อนใช้กับชั้นเรียน ชุดทดสอบจำลองยืนยันตรรกะ แต่ยืนยันการตั้งค่า Google ของแต่ละบัญชีไม่ได้
